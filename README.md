## 4. Решение группового задания

### 4.1. `Product` (Лохмаев)
- `Id` — `required init`; `Title` — `required` с `init`, значение проверяется на пустоту и обрезается по краям;
- `Article` — `required` полное свойство с проверкой на пустоту; `Price` — полное свойство, отрицательное значение запрещено;
- `IsBudget` — вычисляемое свойство (`Price < 25`);
- `Status` — `private set`; меняется только через `ChangeStatus`, допустимые значения: «В наличии», «Нет в наличии», «Под заказ»;
- перегрузки `GetInfo()` и `GetInfo(bool includeIntProperty)`; прежние методы `GetId`, `GetTitle`, `GetPrice`, `SetPrice` оставлены как обёртки над свойствами, чтобы код занятий 2–3 продолжал работать.

```csharp
public required string Title
{
    get => _title;
    init
    {
        if (string.IsNullOrWhiteSpace(value))
            throw new ArgumentException("Название товара обязательно.", nameof(value));
        _title = value.Trim();
    }
}

public int Price
{
    get => _price;
    set
    {
        if (value < 0)
            throw new ArgumentOutOfRangeException(nameof(value), "Цена не может быть отрицательной.");
        _price = value;
    }
}

public bool IsBudget => Price < 25;
public string Status { get; private set; } = "В наличии";

public string GetInfo() => GetInfo(true);

public string GetInfo(bool includeIntProperty)
{
    string info = $"Товар: {Title}, артикул: {Article}, статус: {Status}";
    return includeIntProperty ? $"{info}, цена: {Price}" : info;
}
```

### 4.2. `CustomerProfile` (Останин)
`FullName` — `required init` с проверкой; `Phone` — автосвойство; `Email` — `required` полное свойство, проверка наличия единственного символа `@` в приватном `EnsureValidEmail`; `Rating` — полное свойство с диапазоном 0–5; `IsTrusted => Rating >= 4`. Перегрузки: `GetInfo()`, `GetInfo(bool includeRating)`, `GetContactInfo(bool includePhone)`; приватный `NormalizePhone` оставляет в телефоне только цифры. Проверка e-mail учебная, а не по стандарту.

```csharp
public int Rating
{
    get => _rating;
    set
    {
        if (value is < 0 or > 5)
            throw new ArgumentOutOfRangeException(nameof(value), "Рейтинг должен быть от 0 до 5.");
        _rating = value;
    }
}

public bool IsTrusted => Rating >= 4;

public string GetInfo() => GetInfo(includeRating: true);

public string GetInfo(bool includeRating)
{
    string info = $"Клиент: {FullName}, Email: {Email}";
    return includeRating ? $"{info}, рейтинг: {Rating}" : info;
}
```

### 4.3. `Discount` (Останин)
`Name` — `required init`; `Percent` (0–100) и `MinSum` (≥ 0) — полные свойства; `ValidUntil` — `init`; `IsActive => ValidUntil > DateTime.Now`. Перегрузки `Calculate(int total)` (использует `Percent`) и `Calculate(int total, decimal percent)`. Просроченная скидка не применяется (исключение `InvalidOperationException`); если сумма меньше `MinSum`, возвращается исходная сумма. Расчёт и проверка вынесены в приватные `ApplyDiscount` и `EnsurePercent`.

```csharp
public int Calculate(int total) => Calculate(total, Percent);

public int Calculate(int total, decimal percent)
{
    if (!IsActive) throw new InvalidOperationException("Срок действия скидки истёк.");
    if (total < 0) throw new ArgumentOutOfRangeException(nameof(total), "Сумма заказа не может быть отрицательной.");
    EnsurePercent(percent);
    return total < MinSum ? total : ApplyDiscount(total, percent);
}
```

### 4.4. `CartItem` (Лукьянец)
`readonly struct`; `ProductId`, `Quantity`, `PricePerUnit` задаются только конструктором, который проверяет `ProductId > 0`, `Quantity > 0`, `PricePerUnit ≥ 0`. `Total` — вычисляемое свойство с `checked` (переполнение не остаётся незамеченным). Замечание: у структуры существует значение `default(CartItem)`, созданное без конструктора (`Quantity = 0`), поэтому сервис отсеивает такие позиции методом `IsAvailable`.

```csharp
public readonly struct CartItem
{
    public int ProductId { get; }
    public int Quantity { get; }
    public int PricePerUnit { get; }
    public int Total => checked(PricePerUnit * Quantity);
    // конструктор с проверками — см. файл CartItem.cs
}
```

## 5. Защита свойств: ошибки компилятора

Фрагменты не входят в проект (иначе он не соберётся). Каждый проверялся отдельно в временном проекте командой `dotnet build`.

| Фрагмент | Диагностика компилятора |
|---|---|
| `keyboard.Title = "Новое название";` | `error CS8852`: init-only свойство `Product.Title` можно задавать только в инициализаторе объекта или в конструкторе / `init`-аксессоре |
| `keyboard.Status = "Продан";` | `error CS0272`: свойство `Product.Status` нельзя использовать в этом контексте, так как `set`-аксессор недоступен |

## 8. Выводы

Свойства скрывают внутреннее хранение и собирают проверки в одном месте: недопустимое значение не попадает в объект. `required` гарантирует, что значение задано при создании, но сам по себе не проверяет его содержимое, поэтому в `Title`, `FullName`, `Name` проверка добавлена в `init`. `init` разрешает присваивание только при создании, `private set` — только внутри класса. Вычисляемые свойства (`IsBudget`, `IsTrusted`, `IsActive`, `Total`) не хранят данные и не расходятся с ними. `readonly struct` даёт неизменяемую позицию корзины, но не исключает значение `default`. Перегрузки `GetInfo`, `Calculate`, `GetReport` дают одной операции несколько вариантов вызова; тип возврата в сигнатуру не входит. Без свойств (с публичными полями) проверки пришлось бы дублировать во внешнем коде, и любое место программы могло бы испортить состояние объекта.
