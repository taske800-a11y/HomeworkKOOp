# Задание 2

1. Поле, доступное только внутри класса.

   `private int age;`

   Снаружи класса `student.age` не компилируется.

2. Тип, доступный во всей сборке, но не за её пределами.

   `internal class Product { }`

   Из своей сборки тип виден везде, из другой сборки обращение к нему даёт ошибку компиляции.

3. Вспомогательный тип, доступный только в одном файле.

   `file static class PriceFormatter { }`

   В своём файле тип доступен, в любом другом файле компилятор его не найдёт.

4. Метод, доступный наследникам класса.

   `protected void SetPrice(int price) { }`

   Метод виден в самом классе и в классах-наследниках, снаружи вызвать его нельзя.

5. Наследование от типа с модификатором `file`.

   Из другого файла такой тип не виден, поэтому наследник не скомпилируется: компилятор сообщит, что тип не найден.

6. Что нарушено, если `Catalog` внутри себя создаёт `new FileProductRepository("products.csv")`.

   Нарушен принцип DIP: `Catalog` зависит от конкретного класса, а не от интерфейса `IProductRepository`, поэтому хранилище нельзя заменить, не меняя `Catalog`.

7. Что нарушено, если `Product` хранит данные, сохраняет их в файл и печатает отчёт.

   Нарушен принцип SRP: у класса несколько причин для изменения (данные, хранение, вывод).
